# سُفرة — Full Stack

موقع عربي RTL لغداء الشركة: بوابة موظف ولوحة مشرف بتصميم أبيض وأخضر زمردي، وحضور ذاتي وتصويت موزون بميزانية 900 ريال يمني افتراضياً. React + Vite للواجهات، Express 5 على Node.js 24 للخادم، وSQLite مركزية على قرص الخادم باستخدام `node:sqlite`.

بوابة الموظف تعرض حالة المشاركة والاختيار المحفوظ، ثم تأكيد الحضور ومواعيد اليوم وقائمة وجبات قابلة للبحث بالاسم والمورد، وسجل الاختيارات السابقة. التصميم متجاوب مع الهاتف، مع حالات واضحة قبل النشر وبعد إغلاق الحضور والتصويت. البحث محلي في قائمة اليوم ولا يغيّر الاختيار المحفوظ.

لوحة المشرف تستخدم الهوية البيضاء والخضراء نفسها: نظرة عامة للمشاركة والتصويت ومواعيد الإغلاق، وبطاقات صور لنتائج الوجبات، وإدارة الفريق بالدعوات، وبحث في الوجبات والموردين وسجلات الحضور. تعديلات كميات الكتالوج تحفظ للأيام القادمة دون تغيير قائمة اليوم المعتمدة. القائمة الجانبية تصبح قابلة للفتح على الهاتف، مع جداول قابلة للتمرير الأفقي.

## التشغيل المحلي

يتطلب Node.js **24.13 أو أحدث**.

```powershell
npm.cmd install --cache .npm-cache
npm.cmd run dev
```

افتح **http://localhost:3000**. الواجهة والـAPI يعملان من العنوان نفسه، ولا تحتاج تشغيل Vite منفصلاً. المنفذ 5173 القديم لم يعد عنوان النظام الكامل. يبدأ الخادم على loopback فقط افتراضياً.

في أول زيارة أنشئ حساب المشرف بنفسك. لا توجد بيانات دخول افتراضية، ولا حسابات موظفين أو أصوات أو حضور وهمي. الإعداد الأول مسموح من جهاز الخادم فقط، ويمكن إقفاله بـ`ALLOW_LOCAL_SETUP=false`. كلمات المرور لا تقل عن 12 محرفاً ولا تُخزن كنص.

## تجهيز أول يوم

1. من «الفريق والدعوات»: أضف حساب كل موظف واسمه وقسمه. شارك معه رابط التفعيل خاصاً. الدعوة صالحة 48 ساعة ولمرة واحدة. الموظف يحدد كلمة مروره بنفسه. لا يرسل النظام رسائل أو بريداً تلقائياً.
2. من «إعدادات الشركة»: اضبط الاسم وسقف الفرد، وإحداثيات مركز المبنى ونصف القطر، أو عناوين الشبكة/CIDR. لا توجد إحداثيات شركة مفترضة.
3. من «الوجبات والموردون»: أضف أي عدد من الوجبات، وحدد مورد وكمية كل وجبة دون إدخال سعر. يمكنك التعديل والحذف وتفعيل الخيارات المراد نشرها وتأكيد توفرها. الوجبات الابتدائية اقتراحات غير مؤكدة لا تُنشر تلقائياً. تعديل القائمة أو حذف وجبة لا يغير سجل الأيام المعتمدة. الصور توضيحية من Unsplash.
4. اعتمد خيارات اليوم **قبل 11:00 بتوقيت اليمن**. لا يوجد تجاوز إداري للموعد. تستطيع إعداد القائمة والموظفين بعد الإغلاق لتبدأ في اليوم التالي. تفعيل الاعتماد اليومي التلقائي اختياري بعد تأكيد الخيارات الثلاثة.
5. الموظف يدخل من رابط النظام بحسابه ويضغط زر البصمة لتأكيد مشاركته مباشرة. الوضع الافتراضي «تأكيد ذاتي»؛ لا يستخدم بصمة الجهاز ولا GPS أو الشبكة. يمكن للمشرف لاحقاً اختيار GPS أو الشبكة من الإعدادات، وعندها يلزم استكمال نطاق التحقق؛ إثباته مرتبط بالجلسة والحساب واليوم وصالح دقيقة ولمرة واحدة.
6. الحضور يُغلق 11:00؛ غير المؤكد يصبح غائباً ولا يدخل في العدد. التصويت للمؤكدين حتى 11:15؛ يحسم الخادم الفائز تلقائياً. تنزيل ملخص المطعم لا يرسل طلباً أو ينفذ دفعاً.

المشرف لا يمكنه تأكيد حضور الآخرين، لا من الواجهة ولا من API. حساب المشرف إداري؛ للمشاركة بالغداء يستخدم صاحبه حساب موظف مستقلاً. إيقاف حساب ينهي جلساته ولا يمحو حضوره أو أثره المالي. إعادة إصدار دعوة مفيدة لاستعادة كلمة المرور، ولا تغيرها حتى يفعلها صاحبها.

## قواعد التصويت

صوت واحد قابل للتغيير لكل موظف/يوم. إذا خسر اختياره في الأيام التقويمية الثلاثة السابقة يصبح الوزن 2، ويعيده الفوز أو يوم دون تصويت إلى 1. يستخرج الخادم التاريخ والوزن ولا يقبل وزناً من العميل. أعلى نقاط تفوز، والتعادل بالأقل سعراً ثم معرف ثابت. دون أصوات لا فائز ولا طلب. لا تتغير وجبة اليوم أو سعرها إذا عُدّل كتالوج المورد بعد اعتماد اليوم.

## GPS والشبكة

صور الوجبات: يمكنك إدخال رابط مباشر HTTP/HTTPS (يفضّل HTTPS)، أو رفع JPG/PNG/WebP/GIF حتى 4 ميجابايت من نموذج الوجبة. الملفات تحفظ في مجلد `uploads` بجانب قاعدة البيانات وتبقى بعد إعادة تشغيل الخادم. الروابط الخارجية تحتاج أن يسمح مصدرها بعرض الصورة. أمر النسخ الاحتياطي ينسخ الصور في مجلد ملاصق للنسخة بلاحقة `.uploads`؛ عند الاستعادة أعد محتوياته إلى مجلد `uploads` بجانب قاعدة البيانات. إزالة صورة من الوجبة لا تمحو الملف حتى تبقى صور سجلات الأيام السابقة متاحة.

إذن الموقع يُطلب عند ضغط الموظف، لا تلقائياً. يتحقق الخادم من حداثة القراءة وأن المسافة + هامش الدقة ضمن نصف القطر. لا تُحفظ إحداثيات الموظف في قاعدة البيانات؛ تُحفظ طريقة التأكيد ووقته وإصدار سياسة الشركة. GPS قد يُزوّر ولا يثبت وجود الشخص داخل المبنى؛ لا يوصف كحماية مطلقة.

مطابقة الشبكة تستخدم عنوان اتصال TCP الذي يراه الخادم، مع IPv4/IPv6/CIDR. لا يُقبل عنوان يرسله العميل ولا يُوثق `X-Forwarded-For`؛ `trust proxy=false`. loopback مرفوض. خلف وكيل عكسي سيُرى عنوان الوكيل؛ **لا تضف عنوان الوكيل إلى شبكات الشركة** لأن ذلك قد يقبل جميع زوار الموقع. استخدم GPS أو بنية شبكة داخلية موثوقة قبل تشغيل سياسة الشبكة. الموقع من هاتف عبر HTTP على LAN غالباً محجوب من المتصفح؛ يلزم HTTPS. لا يستطيع الموقع قراءة اسم Wi-Fi/SSID ولا يجمع بصمة بيومترية.

## البيئة

انسخ `.env.example` إلى `.env` عند الحاجة وعدّل القيم. الملف غير متتبع في Git.

| المتغير | القيمة الافتراضية | الغرض |
|---|---|---|
| PORT | 3000 | منفذ التطبيق |
| HOST | 127.0.0.1 | عنوان الاستماع، 0.0.0.0 يحتاج إعداد شبكة مناسباً |
| PUBLIC_ORIGIN | http://localhost:3000 | العنوان الوحيد المسموح للطلبات المغيرة للبيانات؛ يستخدم أيضاً في الدعوات |
| DB_PATH | data/luqma.sqlite | ملف قاعدة البيانات |
| NODE_ENV | development | production يقدم ملفات dist ويتطلب PUBLIC_ORIGIN يبدأ بـhttps |
| ALLOW_LOCAL_SETUP | true في التطوير، false في الإنتاج | السماح بإنشاء المشرف الأول محلياً فقط |

تغيير عنوان التطبيق يتطلب ضبط `PUBLIC_ORIGIN` للعنوان الذي سيستخدمه الموظفون، بما في ذلك المنفذ. لا تعدّل الأصل بناءً على بيانات غير موثوقة من الطلب.

### مشاركة رابط التفعيل داخل الشركة

اضبط `HOST=0.0.0.0` و`PUBLIC_ORIGIN=http://عنوان-IP-جهاز-الخادم:3000` في `.env`، ثم أعد تشغيل الخادم. افتح لوحة المشرف من عنوان IP نفسه حتى تنجح طلبات الإدارة والتفعيل. `localhost` يشير إلى جهاز من يفتح الرابط، وليس جهاز الخادم.

يجب اتصال الموظف بالشبكة الداخلية نفسها وإتاحة TCP 3000 في جدار الحماية للشبكة الداخلية فقط عند الحاجة. لا تفتح منفذ الراوتر للإنترنت. الروابط الجديدة تستخدم العنوان المضبوط تلقائياً؛ الرابط القديم يمكن تصحيح عنوانه مع إبقاء `/join#` والرمز كاملاً إذا لم ينته أو يُستخدم. إعادة إصدار الدعوة تلغي السابقة. يفضل تثبيت عنوان الجهاز لدى مسؤول الشبكة. الاستخدام خارج الشركة وGPS من الهاتف يحتاجان نشر HTTPS مناسباً.

## البناء والتشغيل الدائم

```powershell
npm.cmd run build
```

للإنتاج اضبط `NODE_ENV=production` و`PUBLIC_ORIGIN=https://your-company-domain` و`ALLOW_LOCAL_SETUP=false`، ثم `npm.cmd start`. يُقدّم Express الواجهات والـAPI من خدمة واحدة، وخلف HTTPS تديره البنية المستضيفة. استخدم مدير خدمة يعيد تشغيل Node إذا توقف، ومزامنة موثوقة لساعة الخادم. `npm run preview` يعرض ملفات الواجهة فقط ولا يشغّل النظام الكامل.

يتوفر Dockerfile متعدد المراحل يعمل بمستخدم غير root ويحفظ البيانات في `/app/data`. يجب تهيئة المشرف على قاعدة البيانات محلياً قبل النشر، وربط volume دائم وتعيين `PUBLIC_ORIGIN` الصحيح. لم يُنفذ نشر سحابي أو إعداد DNS/TLS تلقائياً.

## النسخ الاحتياطي والاستعادة

```powershell
npm.cmd run backup
```

ينشئ SQLite Online Backup نسخة متسقة في `data/backups` حتى مع تشغيل الخادم. احفظ نسخة خارج الجهاز بصلاحيات مقيدة وجدول النسخ حسب سياسة الشركة. **قاعدة البيانات تحتوي حسابات وجلسات وبيانات موظفين؛ لا تنشر data ولا .env.**

للاستعادة: أوقف التطبيق، احتفظ بنسخة من البيانات الحالية، واستعد نسخة سليمة إلى `DB_PATH`. لا تستبدل ملف قاعدة أثناء تشغيل الخادم، ولا تخلط ملفات WAL/SHM قديمة مع نسخة مستعادة. اختبر الاستعادة في مسار آخر أولاً وتحقق بـ`PRAGMA integrity_check`. الأرشفة وتحديد مدة الاحتفاظ قرار تنظيمي للشركة؛ لا يوجد حذف آلي لسجلات الحضور.

## الاختبارات

```powershell
npm.cmd test
```

اختبارات HTTP حقيقية وقاعدة مؤقتة: حسابات ودعوات وجلسات وصلاحيات وCSRF وGPS ومواعيد الخادم والإنصاف والتسوية والجدولة والتخزين الدائم. اختبار React في jsdom يتصل بخادم اختباري حقيقي، ويغطي تفعيل حساب موظف وحضوره وتصويته والنتيجة وتسجيل خروجه، ثم دخول المشرف وإنشاء موظف من الواجهة. GPS في الاختبار قراءة محاكية؛ لا يمثل اختباراً هاتفياً أو معاينة بصرية للبكسلات.

التحقق المسجل في جلسة التنفيذ: نجحت 36 حالة اختبار وبناء الإنتاج. اجتاز وضع الإنتاج فحص تقديم صفحة الموظف وملف JavaScript المبني وhealth، ورفض إنشاء مشرف عندما كان الإعداد معطلاً. نجح إنشاء نسخة احتياطية وفحص `integrity_check=ok`. لم تُختبر حاوية Docker أو TLS أو شبكة الشركة الفعلية أو GPS من هاتف فعلي. ظهر تحذير بناء غير مانع بخصوص توجيه `use client` داخل مكتبة الأيقونات.

## حدود الاعتماد

التطبيق مكتمل محلياً لهذه الدورة، وليس ضماناً لمنع الخصم أو تزوير GPS. تأكيد ما قبل 11 لا يثبت استلام الغداء لاحقاً؛ يلزم اتفاق الشركة على المسؤولية ومطابقة المورد. لا يوجد دفع أو إرسال آلي أو SSO أو إشعارات خارجية، ولا يُدّعى تنفيذها. بيانات الحساسية تحتاج معالجة خاصة وبدائل مؤكدة؛ التصويت لا يضمن سلامة الطعام. راجع [التحليل التقني](ANALYSIS.md) و[دليل API](API.md).
